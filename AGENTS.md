## Cursor Cloud specific instructions

- Deploy branch for live Render (`nexa-live` / `nexa-pilot`) is `codex/ai-surveyor-estimator-takeoff`. Prefer landing product work there (or merge into it) rather than stale daywork bases.
- Standard commands: see root `package.json` / `apps/web/package.json` (`pnpm` workspace). Unit tests often run as `node --import tsx --test apps/web/src/lib/<name>.test.ts` from `apps/web`.
- **Blake (tender takeoff)** lives under Tenders → **Blake** tab (was “AI Takeoff”). Commercial / single-building jobs use `set_single_area_project` — do not force housing plot registers. Issued BoQ spreadsheets on Documents can be imported via `import_issued_boq_lines`. Material pricing order: **office materials catalogue (confirmed `costRate`)** → rate library → soft guides → Blake budget. Apply rejects £0 measured lines with no labour. Prefer `listTendersLean` / `getTenderLean` / `leanTenderForClient` in API responses — never echo full BoQ lists from Blake/budget/import routes (OOM risk on Render).
- **Stability**: hub PUT must not echo hub state; Blake chat has `maxDuration` + OpenAI timeouts; React `error.tsx` / `global-error.tsx` recover white-screens. Heap gate on blake-run already refuses near-ceiling memory.
- **Schedule clashes**: hub PUT and lead create/patch hard-block overlaps between `jobSchedulePlans` and lead surveys (`schedule-clash.ts`). Matching uses engineer id or normalised name.
- **simPRO nightly pull**: `nexa-live-simpro-eod` cron in `render-live.yaml` hits `POST /api/integrations/simpro/sync/cron` at **21:00 UTC daily** with leads/quotes/jobs/schedules/invoices/clients/sites. Needs `NEXA_IMPORT_TICK_SECRET` on both the web service and the cron. Working-set caps still apply (recent open records, not full history). Manual Apply is Setup → Integrations. Webhooks are queued only — they do not apply yet.
- **Employee Access**: ticks are enforced. `Engineer` defaults to **Field-only** (`showCore: false`, `showField: true`). Unticked boxes are stored as a full explicit profile on save so they cannot reopen under Owner/Admin merge. Field-only users are redirected to `/field` and Core APIs return 403. Gantt colour is on the employee Details tab (`profile.ganttColor`).
- **Office backups**: Setup → Test restore (dry-run) and Apply restore (type `RESTORE`) write `stores.json` only. Drawing folders / sqlite in the tar remain a manual extract. Needs `NEXA_BACKUP_CRON_SECRET` (+ optional `BACKUP_S3_*`) on Render — **same value** on the web service and its `*-nightly-backup` cron, then restart/redeploy the web service. Cron path `/api/office-backup/cron` is allowlisted in `proxy.ts` (`secretAuthCronPaths`) and is **secret-only** (Setup “Backup now” uses `/api/office-backup`). Check deploy lag via `/api/health` → `deployment.commit` (`nexa-live` is Manual Deploy; `nexa-pilot` auto-deploys). `officeBackup.cronSecretConfigured` is a boolean only. After the allowlist deploy: no/wrong secret → `403`/`503` (not `401 Unauthenticated`). Agents cannot trigger Render Manual Deploy. If live health still shows commit `d56938e…`, nightly backup will keep returning `401 Unauthenticated` until Manual Deploy lands the allowlist fix (`fb5f199+`). If live health still shows commit `d56938e…`, the cron 401 fix is **not** on live yet — Manual Deploy `codex/ai-surveyor-estimator-takeoff` tip (`fb5f199…` or newer).
- **Auth (users mode)**: sessions last 12h; new users / bootstrap admin get `mustChangePassword` and are gated to `/login` until they set a personal password via `/api/auth/change-password`. Full TOTP MFA / SSO is not built yet.
- PDF chrome scrubs placeholder bank + VAT/company. Reports cash owed excludes valuations/credit notes. Field Daywork offline does not permanently lock on queue-only saves.
